# Apache Kafka – Fundamentals and Integration

## 1. Introduction to Apache Kafka

Apache Kafka is a distributed event streaming platform used to publish, store, and process data streams in real time.

It enables different applications and services to exchange data through a reliable messaging system.

In the AtmoSync project, Apache Kafka will be used to stream IoT sensor readings generated by the Python sensor simulator towards the data storage pipeline.

## 2. Why Kafka is Used in AtmoSync

Kafka is included in AtmoSync for the following purposes:

- To transfer sensor readings between different system components.
- To support continuous sensor data streaming.
- To separate data generation from data processing.
- To manage incoming sensor messages through topics.
- To support scalable data pipeline integration.

## 3. Core Components of Apache Kafka

### 3.1 Producer

A Kafka Producer is an application that publishes messages to Kafka topics.

**Role in AtmoSync:**
- Receives sensor readings from the Python simulator.
- Converts or serializes readings into messages when required.
- Publishes sensor data to the designated Kafka topic.

### 3.2 Consumer

A Kafka Consumer is an application that subscribes to topics and reads messages from them.

**Role in AtmoSync:**
- Subscribes to the sensor data topic.
- Retrieves incoming sensor readings.
- Prepares the received data for the Snowflake ingestion process.

### 3.3 Broker

A Kafka Broker is a server that stores and manages Kafka messages.

**Role in AtmoSync:**
- Receives messages from producers.
- Stores messages in topic partitions.
- Makes messages available to consumers.

### 3.4 Topic

A Kafka Topic is a logical channel used to organize messages.

**Example in AtmoSync:**

Topic Name: `sensor_data`

This topic will contain sensor readings such as temperature, humidity, and vibration.

### 3.5 Message

A message is an individual record published to a Kafka topic.

In AtmoSync, each JSON sensor reading will be treated as a message.

### 3.6 Partition

A partition is a subdivision of a Kafka topic that allows messages to be distributed and processed in parallel.

Partitions help Kafka support scalability and higher data throughput.

## 4. Kafka Data Flow in AtmoSync

The planned Kafka workflow is:

1. The Python sensor simulator generates sensor readings.
2. The Kafka Producer publishes readings to the `sensor_data` topic.
3. The Kafka Broker receives and stores the messages.
4. The Kafka Consumer subscribes to the topic.
5. The consumer reads the sensor messages.
6. The received data is forwarded to Snowflake for storage and further processing.
